# 2. CONTEXTE DU PROJET

Le Bénin connaît une croissance importante des événements culturels, professionnels, éducatifs et de divertissement.

Chaque année, de nombreux événements sont organisés :

- concerts ;
- spectacles ;
- festivals ;
- conférences ;
- formations ;
- ateliers ;
- événements universitaires ;
- soirées ;
- événements sportifs ;
- événements religieux ;
- expositions ;
- événements privés ;
- événements d'entreprises.

Cependant, la gestion de ces événements reste souvent fragmentée.

Les organisateurs utilisent généralement plusieurs solutions différentes :

- publications Facebook et Instagram ;
- WhatsApp pour les inscriptions ;
- transferts Mobile Money manuels ;
- listes Excel ;
- billets papier ;
- captures d'écran comme preuve de paiement ;
- validation manuelle à l'entrée.

Cette organisation présente plusieurs problèmes :

- difficulté à suivre les ventes ;
- risque de fraude ;
- faux billets ;
- difficulté à contrôler les entrées ;
- absence de statistiques fiables ;
- gestion manuelle des paiements ;
- difficulté à rembourser les participants ;
- manque de visibilité centralisée des événements ;
- dépendance aux plateformes étrangères.

Le projet vise donc à créer une plateforme numérique spécialisée dans la **création, la promotion, la vente de billets et la gestion complète d'événements**, adaptée au marché béninois.

---

# 3. VISION DU PRODUIT

Créer **la plateforme de référence pour découvrir, organiser et gérer des événements au Bénin**, avec une expérience adaptée aux habitudes de paiement et aux réalités locales.

La plateforme devra permettre à une personne de :

> **Découvrir un événement → réserver ou acheter un billet → payer avec une solution locale → recevoir son billet numérique → présenter son QR Code à l'entrée.**

Et à un organisateur de :

> **Créer un événement → vendre des billets → suivre les paiements → contrôler les participants → analyser les performances de son événement.**

---

# 10. SYSTÈME DE PAIEMENT

## 10.1 Objectif

Permettre aux utilisateurs de payer facilement en FCFA avec les moyens de paiement adaptés au marché local.

---

## 10.2 Moyens de paiement envisagés

La plateforme devra être conçue pour intégrer différents fournisseurs.

Exemples :

### Mobile Money

- MTN Mobile Money
- Moov Money

### Cartes bancaires

Selon les passerelles et partenaires disponibles.

### Paiement via passerelles régionales

La plateforme pourra intégrer une ou plusieurs passerelles de paiement compatibles avec plusieurs pays africains.

---

# 10.3 Architecture du paiement

Le système devra être indépendant du fournisseur.

Une architecture de type **Payment Provider** devra être utilisée.

Exemple :

```text
PaymentService

├── MTNProvider
├── MoovProvider
├── CardProvider
└── RegionalPaymentProvider
```

Cela permettra d'ajouter ou de remplacer un moyen de paiement sans modifier tout le système.

---

# 10.4 Statuts de paiement

- PENDING

- CANCELLED

- EXPIRED

# 10.5 Confirmation du paiement

- redirections ;

- webhooks ;

# 12. QR CODE

Chaque billet devra disposer d'un QR Code unique.

Le QR Code permettra :

- la vérification rapide ;
- le contrôle des entrées ;
- la réduction de la fraude.

---

## 12.1 Règles de sécurité

Le QR Code ne devra pas simplement contenir des informations faciles à modifier.

Le système devra utiliser :

- un identifiant unique ;
- un token sécurisé ;
- une signature ou un mécanisme de validation côté serveur.

---

# 12.2 Statut du billet

Un billet pourra avoir les statuts :

- VALID
- USED
- CANCELLED
- REFUNDED
- EXPIRED

# 14. MODE HORS LIGNE

Cette fonctionnalité pourra être envisagée dans une phase avancée.

- stockage local sécurisé ;
- synchronisation lorsque la connexion revient.

Cette fonctionnalité devra être soigneusement conçue afin d'éviter les doubles validations.

# 55. PRINCIPAUX RISQUES DU PROJET

---

## Risque 1 : Paiements

L'intégration des moyens de paiement peut être complexe.

### Solution

Créer une couche technique indépendante des fournisseurs.

---

## Risque 2 : Fraude

Des organisateurs pourraient créer de faux événements.

### Solution

- vérification ;
- modération ;
- système de signalement.

---

## Risque 3 : Faible adoption

Les organisateurs peuvent préférer WhatsApp.

### Solution

Créer une expérience plus simple que la gestion manuelle.

## Risque 4 : Connexion Internet

### Solution future

Mode hors ligne pour le contrôle des billets.

# 60. CONCLUSION

Le projet vise à créer une infrastructure numérique complète pour l'écosystème événementiel béninois.

La plateforme devra permettre :

### Pour le participant

> Découvrir → Réserver → Payer → Recevoir → Participer.

### Pour l'organisateur

> Créer → Promouvoir → Vendre → Contrôler → Analyser.

L'objectif à long terme est de devenir la référence de la billetterie et de la gestion d'événements au Bénin, avant une éventuelle extension vers d'autres pays d'Afrique de l'Ouest.

# PRIORITÉ PRODUIT

La première version devra absolument réussir ces 5 choses :

1. **Créer facilement un événement.**
2. **Acheter facilement un billet.**
3. **Payer facilement en FCFA.**
4. **Recevoir un QR Code sécurisé.**
5. **Scanner rapidement le billet à l'entrée.**

> Si ces cinq éléments fonctionnent parfaitement, la plateforme possède déjà une véritable base produit.
